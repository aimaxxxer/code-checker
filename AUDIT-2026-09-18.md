# Audit of every repository on this account

18 September 2026. 34 repositories, ~97,000 lines of hand-written source once
vendored bundles are set aside.

## What was actually done

Every source file was parsed and linted mechanically — that part genuinely
covers every line. On top of that, every test suite was run, every server was
booted and probed, and the areas where bugs of this kind usually live were
read by hand. What was *not* done is a line-by-line human reading of all
97,000 lines; that is not something to claim. Where a finding below says
"verified", it means the failure was reproduced and the fix was re-run.

Sweeps run over the whole tree:

| Sweep | Result |
|---|---|
| Python parse (`py_compile`), 84 files | all parse |
| `ruff` pyflakes/bugbear error rules | no runtime bugs; unused imports and f-string nits only |
| JavaScript parse, 141 files | all parse |
| Inline `<script>` in HTML, 48 pages | all parse |
| `eslint` correctness rules (`no-undef`, `no-const-assign`, `no-dupe-keys`, …) | 1 real bug, rest false positives from CDN globals |
| Shell parse (`bash -n`), 20 scripts | all parse, all executable |
| Broken local `src`/`href` in HTML | none |
| Committed-credential scan | 1 real finding |
| Test suites | 5 suites, 1 real failure |
| Servers booted and probed | 7 booted and served |

## The nine fixes

Each is committed on `claude/kind-mccarthy-m813ok` in its own repository and
mirrored in `patches/`.

### 1. vault-brain — two live API tokens committed

`config.json` carried two Obsidian Local REST API bearer tokens and was
tracked, even though the repo's own `.gitignore` has a "Secrets — never
commit" section listing `credentials.json`, `tokens.json` and `secrets.json`.
`config.json` simply was not on that list.

Untracked it, added `config.example.json`, and routed all five entrypoints
through a single `load-config.js` that also reads `VAULT_BRAIN_TOKEN`,
`VAULT_BRAIN_UPSTREAM_TOKEN` and `VAULT_BRAIN_VAULT_PATH`. A fresh clone now
stops with an instruction rather than an `ENOENT`. Verified: 51 of the repo's
own tests pass through the new loader (the 7 failures are notes the test vault
does not contain).

**Both tokens are still in this repo's history and should be rotated in
Obsidian → Settings → Local REST API.** Untracking a file does not remove it
from past commits.

### 2. jarvis — a 4 MB SQLite WAL committed, carrying the database's rows

`.gitignore` covers `*.db`, and `server/jarvis.db` is correctly ignored. But
`jarvis.db-shm` and `jarvis.db-wal` do not match `*.db`, so both were tracked.
The write-ahead log is 4 MB and holds rows from `income`, `investments`,
`habit_log`, `goals`, `todos` and `marktplaats_messages` — so the database the
`*.db` rule exists to keep out of the repo was being committed beside it, and
re-committed on every run.

Added the `-shm`/`-wal`/`-journal` patterns and untracked both files. **These
are also still in history.**

### 3. aether-nexus — paper-trading values could come out NaN

```js
const value = sl.markToMarket ?? (sl.cash + sl.units * (book.lastPrice || 0)) ?? b.capital;
```

`??` only falls through on `null`/`undefined`. The middle operand is
arithmetic, which is never nullish, so `?? b.capital` could not fire. A sleeve
missing `cash` or `units` produced `NaN`, and `NaN` is not nullish either, so
it flowed into `value`, `profit` and `returnPct` and into the UI. `NaN` from
`markToMarket` slipped through the same way.

Now falls back on anything that is not a finite number. Verified against five
shapes: a partial sleeve yields the capital fallback instead of `NaN`.

### 4. claude-brain — a failing test

`shadcn_add.py` moved from a hardcoded `shadcn@latest` to `_get_shadcn_version()`,
which reads the pin from `package.json` and falls back to `2.3.0`. The test
still asserted `shadcn@latest`, so the suite failed. Fixed the assertion and
added the two cases the new logic left untested — the `package.json` pin and
the fallback. 60 tests pass.

### 5. hbt — `--help` started a server

Only `--no-browser` was recognised; everything else, including `--help`, fell
through and launched the app on port 7474, so asking for help started
something the user then had to Ctrl-C. Now prints usage, and exits 2 on an
unknown option. Normal startup unchanged and re-verified.

### 6. gig-agent — `--help` started a real run

Worse than the above: anything that was not `--check` or `--status` fell into
`main()`, so `node src/run.js --help` began searching for work, messaging
Discord and spending model budget. Now prints usage and refuses unknown flags.
A bare run is unchanged; `--check` and `--status` re-verified.

### 7. agenda — a corrupt localStorage entry blanked the page

`hidden: new Set(JSON.parse(localStorage.getItem('hidden') || '[]'))` sat at
module scope, so a corrupt value threw before any of the app ran and the page
came up blank with no way back except clearing storage by hand. A valid
non-array threw too, since an object is not iterable. Now parses defensively.

### 8. sell-week — the same, in `opvolging.html`

`var S = JSON.parse(localStorage.getItem(KEY) || "{}")`, unguarded. A stored
`"null"` also parsed cleanly and then failed on first property access. Now
guarded the way `verkoopweek.html` in the same repo already did it.

### 9. crew — a background thread threw a traceback

The call that opens the browser ran unguarded inside `threading.Timer`, so a
missing `open` dumped a stack trace into the terminal while the server was in
fact running fine. The sibling call twelve lines above was already wrapped.
Now matches it. Verified: one friendly line, server unaffected.

## Worth knowing, not changed

These are judgement calls that belong to you, not defects to fix unasked.

- **`one` and `year-plan` self-tests hardcode Windows paths**
  (`C:\Claude code folder\…`, `C:\Users\oweng\…`), so they only pass on that
  one PC. On this machine 21 of 23 and 111 of 112 checks pass; both failures
  are the paths, not the code.
- **`physique`'s self-test asserts a bedtime exists.** Every other "no data"
  case in that suite is explicitly tested for graceful handling, but this one
  reports a hard failure on a machine that simply has not synced yet.
- **`physique` resolves `ghealth` at `~/Developer/fitbit-air-stats`**, a fixed
  path into another repo. Linked here, its doctor goes green.
- **`aether-nexus` tracks `data/tray.pid`** plus mutable state JSON that
  changes on every run, so running the app dirties the repo. That may be
  deliberate if the state is synced between machines.
- **`claude-brain`'s `ui-styling/requirements.txt` says
  `npx shadcn-ui@latest init`** — the deprecated package name. The code uses
  `shadcn`.
- **`ruff` flags `te` as undefined in `encode_prompts.py`.** It is not: the
  closure runs before the `del te` that confuses the analyser. No change made.
- **Roughly 50 unused imports and placeholder f-strings across `claude-brain`.**
  Cosmetic, and `ruff --fix` handles them if you want them gone.

## The shape of the codebase

Little was found because there is little to find. The self-test suites in
`one`, `year-plan`, `claude-bot`, `crew` and `physique` are unusually
thorough — `year-plan` alone asserts 112 things, including that its Electron
preload exposes nothing the main process does not handle, and `claude-bot`
checks that no secret value reaches a transcript. The two localStorage bugs
and the `crew` traceback were each cases where one site was left unguarded
while its sibling in the same file was not, which is what the sweeps are good
at catching and a reader skims past.

The two credential findings are the ones that matter, and both need a rotation
from you, not a patch.
